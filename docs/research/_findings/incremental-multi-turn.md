# Evaluating Memory in LLM Agents via Incremental Multi-Turn Interactions (MemoryAgentBench)

- **Authors / venue / year:** Yuanzhe Hu, Yu Wang, Julian McAuley — UC San Diego, ICLR 2026
- **arXiv / DOI:** arXiv:2507.05257v4
- **Source:** folder
- **Overall relevance to longmem-npc:** High — its "Selective Forgetting" competency and the FactConsolidation dataset construction method are a near-direct evaluation template for our bi-temporal correction mechanism (fact-level correction + authorial correction), and its headline finding — every memory architecture tested fails badly at multi-hop selective forgetting — is strong external validation that this is a genuinely hard, unsolved problem our design specifically targets.
- **Core contribution (2-3 sentences):** MemoryAgentBench identifies four competencies memory agents need — Accurate Retrieval (AR), Test-Time Learning (TTL), Long-Range Understanding (LRU), and Selective Forgetting (SF) — and builds/reconstructs datasets for each, delivered via a standardized incremental chunk-by-chunk ingestion protocol so evaluation matches how a memory agent actually consumes information (unlike static long-context benchmarks). Evaluating long-context agents, three families of RAG agents, and commercial agentic-memory systems (MemGPT, MIRIX, Mem0, Cognee, Zep, etc.), it finds RAG wins on AR, long-context wins on TTL/LRU, and **all** methods fail SF — especially multi-hop forgetting, where no method exceeds 28% accuracy.

### Mechanisms relevant to us
- Four-competency taxonomy (AR / TTL / LRU / SF) as an organizing structure for a memory eval suite, explicitly grounded in memory-science distinctions (retrieval vs. consolidation vs. integration vs. interference/forgetting) (§1, citing James 1890; McClelland et al. 1995; Anderson & Neely 1996).
- Incremental ingestion protocol: all agents are fed `c1, c2, ..., cn` chunks one at a time with an explicit "memorize this" instruction, then queried only after full ingestion — modeling real multi-turn accumulation rather than single-shot long-context stuffing (§3.3).
- **FactConsolidation dataset construction** (the Selective Forgetting eval): built from MQUAKE counterfactual edit pairs — each pair is a true fact plus a rewritten, contradictory version; the rewritten (newer) fact is always placed *after* the original in the context, at controlled lengths (6K/32K/64K/262K tokens); the agent is explicitly told facts carry serial numbers and "newer facts have larger serial numbers," and must resolve conflicts by finding the newest fact. Two variants: single-hop (direct fact recall) and multi-hop (the answer requires composing a corrected fact with another fact) (§3.1, "Datasets for Selective Forgetting").
- Headline SF result: "all methods fail on the multi-hop situation (with achieving at most 28% accuracy)... Only long context agents can achieve fairly reasonable results on single-hop scenarios" (§4.2, finding 3) — a strong, reproducible field-wide result that knowledge-update reasoning collapses under composition, even though the models are explicitly told which fact is newer.

### NOT-YET-BUILT candidates (a capability we simply don't have)
- **Capability:** A "Selective Forgetting" eval category: insert a fact, later insert a contradicting update, then query and score whether the answer reflects the corrected/current state rather than the stale one — including a **multi-hop** variant where the answer requires composing two separately-corrected facts.
- **What the paper does:** — *evidence:* §3.1, FactConsolidation construction ("the rewritten (new) fact appears after the original... Agents are prompted to prioritize later information in case of conflict"); §4.2, "Limitation of All Existing Methods on Selective Forgetting... forgetting out-of-date memory poses a significant challenge."
- **Why worth adopting for an NPC memory service:** This is the single most direct mapping in the whole batch to something we've built but never judged: fact-level correction (migration 002) and authorial correction supersede via `invalid_at` and re-embed the fact head so "retrieval follows the fix" — but that claim has only been proven structurally (the live head flips in the DB, a walker asserts distance-0 rank order in a *small*, controlled fixture). MemoryAgentBench's finding that even models explicitly told "the newer fact wins" still fail at ~28% on multi-hop composition is a serious warning: our retrieval-follows-the-fix guarantee has never been tested (a) in a populated store where the stale fact's embedding still has residual similarity pull, or (b) in a scenario requiring the *dialogue* call to compose a corrected fact with another unrelated fact. Both are realistic demo/production conditions we currently have zero coverage of.
- **Adoption cost/risk in our stack:** Low-to-medium. No schema change — reuses the existing authorial/fact-level correction verbs. New work is purely eval harness: seed a populated store, issue a correction, populate distractor facts, then judge the dialogue turn's answer. The multi-hop variant additionally requires a two-correction scripted scenario.

### THESIS-TENSION flags (conflicts with an invariant — surface, don't force)
- **Invariant challenged:** None directly — but "Test-Time Learning" (TTL), one of the paper's four core competencies, has no analog in longmem-npc's design and is worth naming explicitly so it isn't silently assumed missing-by-oversight.
- **What the paper does that conflicts:** — *evidence:* §1, TTL is defined as "The capacity to incorporate new behaviors or acquire new skills during deployment, without additional training" (e.g., in-context intent classification from labeled examples accumulated over a session).
- **Honest read:** This is a genuine scope difference, not a weakness. longmem-npc's memory is episodic/identity content (what happened, how the character currently tells it), not a skill/behavior-acquisition mechanism — the closest thing we have (the post-August parameter compiler / reflection→behavior-bias pipeline) is designed, not built, and is oriented at shifting stance/action-bias priors from reflection, not at in-context task learning in MemoryAgentBench's sense (classification-from-examples). Worth stating plainly if this paper is cited: we are not claiming TTL coverage, by design, not by gap.

### Quotable lines / citations for positioning (optional)
- "Although being a well-discussed task in model-editing community... forgetting out-of-date memory poses a significant challenge on memory agents. We observe that all methods fail on the multi-hop situation (with achieving at most 28% accuracy)" (§4.2) — strong, citable evidence that fact-conflict resolution over long-term memory is an open field-wide problem, directly motivating our bi-temporal correction design as addressing a validated gap rather than a self-invented one.

### Verdict
P1 adopt-soon: build a Selective-Forgetting eval category modeled directly on FactConsolidation (single-hop and multi-hop variants) against our fact-level/authorial correction — it is the best-evidenced, most field-validated gap in this entire batch, and the one closest to something longmem-npc already claims to solve but has never judged end-to-end in a populated, competing-embeddings store.
