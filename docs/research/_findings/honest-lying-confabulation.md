## Honest Lying: Understanding Memory Confabulation in Reflexive Agents

- **Authors / venue / year:** Prakhar Dixit, Sadia Kamal, Tim Oates (UMBC) — ICML 2026 Workshop "Failure Modes in Agentic AI" (arXiv, 2026-05-28, v2 2026-05-31).
- **arXiv / DOI:** 2605.29463v2 — https://arxiv.org/abs/2605.29463
- **Source:** discovered
- **Overall relevance to longmem-npc:** Medium-High — not about game NPCs, but it names and measures the exact failure mode ("memory confabulation") our thesis's signature term describes, in a setting (Reflexion-style self-generated reflective memory) that is structurally close to our sequenced-later Reflection pipeline. It's the strongest available cautionary evidence for how NOT to build that pipeline, and a validating contrast for why our design keeps confabulation confined to the telling layer.
- **Core contribution (2-3 sentences):** Reflexion-style agents that write self-generated natural-language reflections as their only memory can confabulate: across ALFWorld, 16 of 50 environments produce "frozen" memory where the agent stores a confidently wrong account of the task and reuses it for an average of 7.6 trials (vs. 1.5 for non-frozen environments), with 0 of 121 reflections in those environments even mentioning the correct target object. The paper shows this is causal (removing memory entirely solves 2 of those environments faster) and that the fix is not better reflection prompting in the abstract, but grounding the reflection in programmatically-extracted trajectory facts rather than open-ended self-diagnosis — raising correct-object mention from 0% to 86% and cutting the repetition metric (RRR) from 0.64 to 0.10.

### Mechanisms relevant to us
- **Memory confabulation, operationalized**: "a reflection r_t is confabulated if it fails to mention the correct target object of task τ" (§3.1) — a concrete, measurable definition, not just a description of hallucination.
- **Reflection Repetition Rate (RRR)**: a log-based diagnostic (SequenceMatcher similarity ≥0.85 between reflections) that correlates with trials-to-solve at r=0.808 (§3.2, §4.1) — a cheap way to *detect* that reflective memory has stopped evolving and is reinforcing a stale belief.
- **Causal ablation**: wiping memory entirely before each trial solves 2/16 "memory-harmful" frozen environments faster than the reflection-equipped agent (7-8 trials → 1 trial) — direct evidence that unvalidated self-generated memory can be actively worse than no memory (§4.4).
- **Two mitigations, both about write-path validation, not retrieval**: (1) "Grounded Reflection" — force the reflection to quote an exact trace step before planning; (2) "Programmatic Feedback Extraction" — replace open-ended self-diagnosis with a parser that extracts concrete failure signals (e.g. which action got "Nothing happens") and injects them into the reflection prompt (§5.1-5.2).
- **Cross-domain finding**: frozen-memory rate tracks feedback granularity, not model size — binary pass/fail feedback (ALFWorld 32%, WebShop 82%) confabulates far more than step-level feedback (HumanEval 17%); a stronger model (gpt-4o-mini) eliminates *task-identity* confabulation but does not fix the underlying capability gap, "confirming that task-identity confabulation and task-level capability are independent failure axes" (§6.2).

### NOT-YET-BUILT candidates (a capability we simply don't have)
- **Capability:** write-path grounding/validation for reflective memory writes — a gap that doesn't exist yet because our Reflection pipeline (sampling episodes, revising seed identity, pruning identity-components) is itself not yet built.
- **What the paper does:** shows that when a reflective-memory write is *not* grounded in concrete, parseable evidence, it can silently confabulate and then compound across trials because "the false content is stored, retrieved, acted upon, and reinforced by later reflections" (§2, "Hallucination and confabulation"). Their fix generalizes as a design principle, not a specific technique: prefer programmatically-extracted, concrete evidence over open-ended LLM self-diagnosis whenever the memory write is meant to durably influence future behavior.
- **Why worth adopting for an NPC memory service:** our Reflection pipeline will eventually do something structurally similar to Reflexion's self-critique — sample past episodes and have a model conclude something durable about the NPC's identity/behavior. This paper is direct, measured evidence that an ungrounded version of that step can silently poison the NPC's self-model, and that the poisoning would be invisible without something like an RRR-style repetition/staleness check. Concretely, when reflection is specced, its write step should (a) ground conclusions in specific retrieved memory_ids/spans rather than open-ended summarization, mirroring their "quote a specific trace step" fix, and (b) budget for a validation or staleness signal analogous to RRR before an identity revision is trusted.
- **Adoption cost/risk in our stack:** low as a design input (no code today); when reflection is eventually specced, "ground each conclusion in cited memory_ids" is cheap to require given we already return memory IDs on every read (invariant #6) and already NER/embed at write time — the citation-checking infrastructure is mostly already present.
- **Docs it would touch:** the eventual reflection spec (sequenced-later, mechanism undesigned).
- **Confidence:** High that the risk is real and worth designing against; Medium on exact mechanism transfer since Reflexion's binary pass/fail setting is not identical to our importance×recency episode sampling.

### Quotable lines / citations for positioning (optional)
- "A memory system that stores confident, plausible-sounding but wrong beliefs is worse than no memory at all for the tasks those beliefs affect." (Conclusion) — a strong, citable line for the README's framing of why controlled infidelity needs an immutable record underneath it, not just a self-consistent narrative.
- "Designing agents that know when not to write or that validate causal accuracy before storing is a necessary complement to the retrieval improvements that have dominated recent work." (Conclusion) — supports our "instrument at the seam" / degradation-ladder discipline extended to a future reflection write path.
- "The false content is stored, retrieved, and acted upon persistently across multiple trials" as the definition distinguishing confabulation from ordinary single-generation hallucination (§2) — useful for sharpening our own terminology: our thesis's "controlled infidelity" is precisely an architecture where the *telling* can drift (confabulate, in their sense) while the record it drifts from cannot be touched — this paper's failure mode is what happens when there is no such record underneath the drifting layer at all.
- Worth noting for positioning, not adoption: ExpeL's rule-library extension "shares the same structural vulnerability... but with amplified consequences: where Reflexion confabulates per-task reflections, a confabulated rule... becomes entrenched and is applied across every evaluation environment" (§2, §6.3) — a good cautionary data point if we ever consider a shared cross-NPC rule/parameter-compiler layer (our post-August "parameter compiler" line), since that design has the same amplification shape.

### Verdict
P2 worth-piloting — not adoptable as code today since it's a warning about a mechanism (reflection) we haven't built, but it should be read before that spec session: it gives a named failure mode (memory confabulation), a cheap detector (RRR-style repetition check), and a concrete mitigation direction (ground reflective writes in cited evidence, not open self-diagnosis) that reflection's eventual design should account for from the start rather than discover the hard way.
