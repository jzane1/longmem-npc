## Structured Episodic Event Memory (SEEM)

- **Authors / venue / year:** Zhengxuan Lu, Dongfang Li, Yukun Shi, Beilun Wang, Longyue Wang, Baotian Hu — 2026 (arXiv, v2 2026-02-10).
- **arXiv / DOI:** 2601.06411v2 — https://arxiv.org/abs/2601.06411
- **Source:** discovered
- **Overall relevance to longmem-npc:** High — its central mechanism (Reverse Provenance Expansion) is a retrieval-time answer to exactly the gap our baseline names as "no graph/associative structure over memories... no multi-hop retrieval," and its "associative fusion" write step is a useful, honest counter-example against non-destructive storage.
- **Core contribution (2-3 sentences):** SEEM extracts each interaction passage into a structured Episodic Event Frame (participants/action/time/location/reason/manner + summary), fuses frames judged to describe the same event while unioning their source-passage provenance pointers, and separately builds a schema-agnostic relational graph over extracted fact quadruples. At retrieval time, Reverse Provenance Expansion (RPE) uses a retrieved frame's aggregated provenance pointers to pull in *every* passage that was fused into it, reconstructing a complete narrative context from otherwise-scattered fragments; this beats HippoRAG 2 by 4.4% accuracy on LongMemEval.

### Mechanisms relevant to us
- **Episodic Event Frames** — LLM-parsed, multi-attribute structured units (Participants/Action/Time/Location/Causality/Manner) grounded to source text via provenance pointers (§3.2.1).
- **Associative Fusion** — when a new candidate frame is judged the same event as a prior one, an integration agent merges attributes and *unions* the provenance-pointer sets rather than picking one (§3.2.2).
- **Reverse Provenance Expansion (RPE)** — retrieval-time: once a frame is activated, expand the evidence set to include every passage in that frame's aggregated provenance, "so that if any fragment of an event is activated, all its constituent textual supports are included in the final context" (§3.4.2, Eq. 5).
- **Redundancy analysis** (§B.4): mean cosine similarity between the graph layer's facts and the episodic layer's frames for the same query is only 0.46 — evidence the two layers capture genuinely complementary information rather than duplicating each other.
- Ablation (Table 4): removing RPE, removing the graph layer, and removing EEFs each measurably hurt performance; removing RPE specifically "leads to fragmented evidence, which negatively impacts reasoning quality" (§5.3).

### NOT-YET-BUILT candidates (a capability we simply don't have)
- **Capability:** cross-observation associative expansion at retrieval/reconstruction time — our baseline's noted gap: "No graph / associative structure over memories (no entity graph, no linking beyond identity-components + gist spans + entities[]). No multi-hop retrieval."
- **What the paper does:** RPE reconstructs a coherent context by following provenance links accumulated during write-time fusion — retrieving one fragment of a multi-turn event pulls in every other passage that contributed to it (§3.4.2). The mechanism is explicitly framed as solving "scattered retrieval, where the retrieved context is fragmented into isolated pieces" (§1).
- **Why worth adopting for an NPC memory service:** our gist system already stores spans as pointers into `observation_text` (immutable, non-rewritten) — conceptually close to SEEM's provenance pointers — but gist matching operates *within* one observation, with no mechanism to link related gist/detail across *separate* observations. RPE-style linking would let a query that surfaces one memory about "the merchant's debt" also surface an earlier, textually-dissimilar observation about "the merchant borrowing coin" that never shares vocabulary with the query — directly the kind of associative recall a long-running NPC relationship needs and that flat cosine similarity misses.
- **Adoption cost/risk in our stack:** substantial — this is new-migration territory (an edge/link table connecting `memories`/`memory_fact_versions` rows, populated at write time by an LLM-judged similarity/same-event check analogous to `Fjudge`). It would need its own cost/latency budget (an extra LLM call per observation to decide fusion, per §3.2.2) and would have to be designed to respect non-destructive storage explicitly — see THESIS-TENSION below, where SEEM itself does not.
- **Docs it would touch:** a new migration + `architecture.md` §4.4/§7 (reconstruction's fixed-constraint input could reasonably absorb linked-frame spans the same way it absorbs gist today).
- **Confidence:** Medium — the retrieval-time mechanism (expand via provenance) is well-evidenced and portable; the write-time fusion-judgment step is the costlier, riskier half to adapt safely into our model.

### THESIS-TENSION flags (conflicts with an invariant — surface, don't force)
- **Invariant challenged:** #1, bi-temporal non-destructive storage ("never UPDATE stored content in place").
- **What the paper does that conflicts:** associative fusion appears to *mutate* the existing frame in place rather than version it — "the integration agent F_fuse performs an associative merge, synthesizing the attributes of both frames and updating the summary v_sum... updating t_eml to point to the union of all involved source passages" (§3.2.2, emphasis on "updating"). There is no chain, no `invalid_at`, no prior-fused-state preservation described anywhere in the paper. The paper's own Ethical Considerations section admits the consequence directly: "the system is susceptible to error propagation, where inaccuracies in the initial LLM-based extraction or fusion phases can permanently corrupt the structured memory store" (Limitations).
- **Honest read:** this is a genuine weakness in SEEM's design relative to ours, not an apples-to-oranges mismatch — both systems are solving "how do I keep a coherent narrative account of scattered events," and SEEM's answer trades away recoverability for coherence at write time. This is a strong, citable positioning contrast: our bi-temporal chain (supersede via `invalid_at`, never delete) gets the same "coherent current telling" benefit SEEM's fusion aims for, *while* keeping every prior state independently queryable — SEEM has no analogous safety net if a fusion judgment (`F_judge`) is wrong, and says so itself.

### Quotable lines / citations for positioning (optional)
- "The system is susceptible to error propagation, where inaccuracies in the initial LLM-based extraction or fusion phases can permanently corrupt the structured memory store." (Limitations) — directly usable in the README's destructive-compression counter-example slot; a paper's own admitted risk rather than our inference.
- "Scattered retrieval, where the retrieved context is fragmented into isolated pieces, failing to provide the coherent narrative required for complex reasoning." (§1) — good framing language for why reconstruction/gist-linking matters at all.

### Verdict
P2 worth-piloting: RPE-style cross-observation provenance linking is a well-evidenced, genuinely new capability that maps directly onto our named graph/associative-memory gap, but it's a real build (new migration, new write-time cost) — worth a future spec session, not a quick add. The paper's own admission of irrecoverable fusion errors is a strong, ready-made positioning citation for our non-destructive design, usable now at P1 for the README/write-up regardless of whether RPE itself is ever built.
