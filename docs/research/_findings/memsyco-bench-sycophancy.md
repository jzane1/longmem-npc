# MemSyco-Bench: Benchmarking Sycophancy in Agent Memory

- **Authors / venue / year:** Zhishang Xiang, Zerui Chen, Yunbo Tang, Zhimin Wei, Ruqin Ning, Yujie Lin, Qinggang Zhang, Jinsong Su (Xiamen University, Jilin University) — 2026, "Work in Progress" preprint.
- **arXiv / DOI:** arXiv:2607.01071v2 — https://arxiv.org/abs/2607.01071
- **Source:** discovered
- **Overall relevance to longmem-npc:** High — this is an evaluation harness for whether a retrieved memory *should* be allowed to influence the current answer at all, which is the exact question our authorial-correction / fact-following / gate stack is trying to answer architecturally but has no test coverage for at the "does the model actually obey the corrected/valid memory" level.
- **Core contribution (2-3 sentences):** The paper defines "memory-induced sycophancy" — an agent letting a retrieved historical memory (belief/preference/prior statement) override objective evidence, scope, or a later update — as a failure mode distinct from ordinary in-context sycophancy, because the influence comes from a *persisted* memory store rather than the current turn. MemSyco-Bench is a 5-task benchmark (reject memory as evidence / respect scope / resolve memory-vs-evidence conflict / select the currently-valid memory / use valid memory for personalization) built via a schema-first pipeline that fixes the correct memory-use boundary before generating the dialogue and question. Across 7 memory systems (Mem0, A-Mem, LightMem, MemGPT, MemoryBank, SuperMemory, NaiveRAG) and 2 backbones, existing memory systems are shown to *increase* sycophancy relative to a no-memory baseline in most tasks, and 61–62% of errors occur *after* correct retrieval (post-retrieval misuse, not a retrieval miss).

### Mechanisms relevant to us
- **Memory-decision schema construction (§3.3):** every benchmark instance is built from a frozen schema specifying task goal, answer space, required info, and *the intended role of memory in the decision* — before the dialogue is generated. This inverts the usual retrieval-then-question pipeline and is a reusable design for testing whether a system's use of memory matches an intended policy.
- **VALID MEMORY SELECTION task** — tests whether an agent, given a memory bank containing a value the user later reversed/updated, answers from the *current* value or the obsolete one, without the query stating which memory to use (§3.2). This is a direct behavioral analogue of our fact-version-chain / authorial-correction "retrieval follows the fix" invariant, but evaluated end-to-end through generation rather than at the SQL layer.
- **MEMORY-EVIDENCE CONFLICT task** — tests whether the agent follows verified/objective evidence over a stored user memory when they conflict (§3.2); this maps to our (currently unbuilt) dissonance/diegetic-correction path, where store truth and character reaction are meant to diverge.
- **Error attribution methodology (R+/A+, R+/A-, R-/A- quadrants; §2.2, §4.2):** cleanly separates "couldn't find it" from "found it but used it wrong" — the paper shows existing benchmarks (including LongMemEval, LoCoMo, STALE, PersonaMem, which we already hold) are dominated by the R-/A- (retrieval-failure) quadrant and essentially untested on R+/A- (misuse-after-correct-retrieval), which is precisely the failure mode our correction/gate machinery targets.

### NOT-YET-BUILT candidates (a capability we simply don't have)
- **Capability:** A behavioral test that memory *validity* (as opposed to retrieval success) is respected at generation time — baseline gap: "No end-to-end evaluation harness... no memory-conflict or staleness eval."
- **What the paper does:** Constructs paired natural dialogues where a stale/scope-inappropriate/contradicted memory is deliberately retrievable, and scores whether the final answer follows it anyway — *evidence:* §3.4, Table 1: for Qwen3-8B, adding any tested memory system to OBJECTIVE FACT JUDGMENT questions *drops* accuracy from 49.12 (no memory) to 26.00–36.00 and *raises* sycophancy rate from 27.43 to 44.47–64.67; on VALID MEMORY SELECTION, "outdated memory use... rises from 56.16 under Full Dialog to 50.57-69.91" for several systems — i.e., adding a memory system can make agents *more* likely to use the wrong (superseded) fact, not less.
- **Why worth adopting for an NPC memory service:** Our architecture has several places designed exactly to prevent this failure — the fact-version one-live-head constraint, the authorial-correction CAS, the reconstructor's corrected-head-as-fixed-constraint rule, and (eventually) the dissonance path's store-truth-vs-character-reaction split. None of them are currently tested at the "does the dialogue call's actual prose obey the corrected data" level; our structural pytest suite (`tests\test_set_a_correction.py` etc.) checks that the SQL and service layer route correctly, not that the LLM-generated turn text reflects it. A MemSyco-Bench-style harness — built around our own `:correct` / diegetic-correction seams — would close that gap, and would give a concrete regression signal for the escalation/dissonance work still owed.
- **Adoption cost/risk in our stack:** Moderate-low for the "VALID MEMORY SELECTION" analogue (we already generate the fixture data structurally — a corrected memory with a known old/new value — the missing piece is judging the *dialogue* output, which requires an LLM-judge step outside the structural-only test philosophy, so it would sit alongside, not inside, the Stop-hook suite). Higher for "MEMORY-EVIDENCE CONFLICT" since our system has no first-class "objective/verified evidence" input distinct from stored memory (that would be new to design, likely riding on the dissonance/diegetic-correction spec).
- **Docs it would touch:** Same eval-harness home as the Memora/FAMA finding (new `docs/eval-harness.md` or an addendum to `test-suite.md`'s research-track note); potentially informs the still-unbuilt dissonance mechanism spec (`architecture.md` §7-adjacent) with a concrete "does the reaction leak store-truth or over-comply with player-asserted belief" test shape.
- **Confidence:** Medium-High — the five-task taxonomy and schema-first construction method are concrete and reusable; the paper is explicitly "Work in Progress" (its own label), so cite it as a methodology source rather than a settled benchmark.

### Quotable lines / citations for positioning (optional)
- "the central challenge for memory-enabled agents is not only retrieving relevant memories, but deciding when and how retrieved memories should influence reasoning." (§1) — good framing line distinguishing retrieval quality from use-of-memory correctness, a distinction our architecture already makes structurally (gate vs. reconstruction vs. dialogue) but doesn't yet measure end-to-end.
- "61–62% of all errors occur after the relevant memory has already been retrieved" (§4.2, Obs.4) — strong citation for why a retrieval-only eval (which is most of what exists, including our own structural walkers) understates the real risk surface.

### Verdict
P2 worth-piloting: the task taxonomy (especially VALID MEMORY SELECTION and MEMORY-EVIDENCE CONFLICT) is directly reusable as a generation-level regression check for our correction/gate/dissonance stack, complementary to Memora/FAMA rather than redundant with it (this paper probes *use*, FAMA probes *inclusion/exclusion*). Lower priority than a build task; natural home is alongside the still-open eval-harness gap.
