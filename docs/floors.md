# longmem-npc — Verified floors

Split out of `status.md` on 2026-07-28 (full-repo audit). The table lived inside the
auto-loaded living file, where it cost ~8.7k tokens of every session's context and had
drifted: blank lines between rows broke the GFM table after row 8, so the ten most recent
floors did not render as a table anywhere, and the headline count disagreed with the rows.
Rows are moved **verbatim** — no cell text was edited. *(One exception, noted 2026-07-29: the
Target-A row's `Research Papers\` pointer became `docs\research\` when the audit's phase 7 moved
that folder into the repo — a path fix during propagation, not an evidence edit.)*

**Append-only.** A row lands here only after an independent floor-verifier pass returns
**pass** (CLAUDE.md: staged verification). Never edit a landed row except to add a dated
supersede note; floors are re-openable, and a re-opened floor is re-verified, not rewritten.

**Counting convention** *(stated 2026-07-28 — its absence was the source of the drift)*: the
table has **18 rows**, and every row is a verified floor. Earlier prose in `status.md`
counted "sixteen" against eighteen rows because it silently excluded the two rows that are
not application layers — the Postgres/pgvector container + read-only MCP row, and the
structural pytest suite row. Both ARE verified floors and both are counted here. When you
cite a count, cite this table.

Each "Verified against" cell records what was actually re-run: the walker and its assertion
count, the prior floors re-checked, the migration state, the product-DB pristine check, and
any live beat. That cell is the evidence, not a summary of it.
